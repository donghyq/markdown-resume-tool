## 项目经历

### 01 大模型 API 服务性能与稳定性优化 | 2024.02—2025.01

> vLLM / FastAPI / Python asyncio / Prometheus

**项目背景：**多个业务共用模型 API，高峰期请求排队、超时与取消处理不一致，影响响应速度，也让失效请求继续占用计算资源。

- **统一请求管理：**实现流式响应、请求限流、超时传递与客户端断开检测；将取消信号传至模型服务，及时释放失效请求占用的资源，并提供统一错误码与重试建议。
- **批处理参数优化：**按输入长度、输出上限和并发数组织压测，调整批处理容量与排队策略；在固定硬件和请求分布下，示例压测的首 Token 时延 P95 **1.9 秒→1.2 秒**。
- **服务健康与降级：**增加排队时间、生成速度、错误率与实例健康监控；区分容量不足与实例故障，支持请求转移和并发保护。示例高峰期请求成功率 **96.5%→99.1%**。

### 02 多团队 GPU 资源分配与任务排队平台 | 2023.01—2023.12

> Kubernetes / NVIDIA GPU Operator / Kueue / DCGM

**项目背景：**算法团队共享 GPU 集群，任务提交依赖人工协调，部分资源长期空闲，而高优先级任务仍需等待，使用情况也难以追踪。

- **任务队列与团队配额：**统一训练和离线推理任务入口，按团队设置资源配额与任务优先级；提交时校验 GPU 型号、数量和运行环境，让等待原因与可用资源对用户可见。
- **GPU 监控与闲置治理：**采集利用率、显存占用和设备健康数据；识别长时间无有效计算的任务，通知使用者确认后释放资源，保留任务信息与处理记录。
- **容量分析与调度验证：**按团队汇总资源使用与排队情况，结合任务规模调整配额。虚构演示中，GPU 平均利用率 **41%→63%**，任务排队中位时间 **46 分钟→25 分钟**。

### 03 训练数据处理与质量校验流水线 | 2024.06—2025.06

> Apache Spark / Ray Data / Parquet / S3

**项目背景：**训练数据来自不同业务，格式、编码与字段质量不一致；重复样本和数据批次混用会拖延训练，也使评估结果难以复现。

- **统一样本格式与质量检查：**解析文本和结构化数据，校验必填字段、编码和长度；将不合格记录写入隔离目录，按批次输出质量统计，便于数据负责人定位来源问题。
- **重复数据与评测隔离：**结合精确匹配和文本相似性筛选重复样本，按数据来源与时间划分训练集、验证集和测试集；记录处理规则与数据版本，减少评测数据混入训练集的风险。
- **并行处理与稳定输出：**按数据规模组织并行任务，将结果写成大小适中的 Parquet 文件；失败时重试受影响的任务，避免重复处理整批数据。示例批次处理时间 **7.2 小时→3.6 小时**。

### 04 模型发布评测与服务可观测性建设 | 2025.07—至今

> MLflow / Argo CD / OpenTelemetry / Grafana

**项目背景：**模型更新依赖手工修改部署配置，版本、参数与评测结果分散保存，发布后出现性能回退时难以定位，也缺少统一的恢复操作。

- **版本管理与发布校验：**关联模型版本、容器镜像、运行参数和评测报告；发布前检查配置兼容性、基础功能与性能阈值，通过检查后才允许进入小流量验证。
- **分批发布与快速回退：**按预设比例逐步扩大流量，持续检查错误率、响应时延与输出质量；指标超过阈值时停止扩大流量，并恢复上一稳定版本，记录触发原因和实际恢复结果。
- **请求追踪与故障定位：**串联请求接收、排队、模型处理和响应传输过程，在看板中关联链路、日志与资源指标。示例演练的故障定位时间 **35 分钟→12 分钟**。
